# 笔记规范

## 目标

3 分钟内能找到结论；不读全文也能用。

## 硬性规则

1. 一篇一个主题，**≤ 120 行**；超了拆篇。
2. 第一段必须是**结论**，3 行以内。
3. 用表格和清单，不写长段落；删掉「首先 / 然后 / 总的来说 / 值得注意的是」。
4. 代码只贴关键片段（**≤ 15 行**），不整段抄源码；其余给文件路径 + 行号。
5. 待办必须是可勾选项，并带验收标准。
6. 不复述常识，不解释「什么是引用计数」这类背景。

## 固定结构

```
# 标题
> 日期 | 分支 | 状态

## 结论
## 问题
## 方案
## 验证
## 遗留
## 相关文件
```

- 没有内容的章节直接删掉，不写「暂无」。
- 计划 / TODO 用 `- [ ]` 清单，不用长段落。

## 文件命名

| 类型 | 位置 | 命名 |
|---|---|---|
| 学习笔记 | `Notes/<分类>/` | `kebab-case.md` |
| 决策 / 重构 | `Design/` | `yyyy-mm-dd-topic.md` |
| 计划 / TODO | `Design/` | `yyyy-mm-dd-topic-plan.md` / `-todo.md` |

图片放 `Docs/assets/`，用相对路径引用。

## 状态标记

`草稿` / `进行中` / `已完成` / `已废弃`

## 提交前自检

- [ ] 3 行内能说出结论
- [ ] ≤ 120 行
- [ ] 没有复述常识
- [ ] 代码片段 ≤ 15 行
- [ ] 关键结论带文件路径
- [ ] 已加入 `Docs/README.md` 索引

> 仓库是公开的：不要写账号、密钥、公司内部信息。
